# План развёртывания и отката

## Перед релизом
- Сделать резервную копию PostgreSQL.
- Проверить переменные окружения и доступность Redis.
- Выполнить `python manage.py check --deploy`.
- Выполнить тесты и `python manage.py migrate --plan`.
- Проверить совместимость миграций с текущей версией приложения.

## Развёртывание
1. Собрать новый образ.
2. Запустить миграции.
3. Запустить web и worker.
4. Проверить `/health/live/` и `/health/ready/`.
5. Проверить логи, 5xx rate, latency и очередь Celery.

## Откат
1. Остановить выдачу трафика новой версии.
2. Вернуть предыдущий Docker image.
3. Если миграции обратно совместимы — выполнить документированную обратную миграцию.
4. Если миграция разрушительная — восстановить БД из backup по согласованной процедуре.
5. Проверить health endpoints и контрольные API-запросы.

## Резервное копирование
Пример для PostgreSQL в Docker:
`docker compose exec -T db pg_dump -U postgres backend_db > backup.sql`

Восстановление выполняется только после проверки файла и согласования окна восстановления.
